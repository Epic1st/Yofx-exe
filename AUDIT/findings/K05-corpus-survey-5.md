## Verdict
The 60 scoped files exhibit serious hygiene and transpilation issues: multiple strategies depend on non-existent header files (`<Calendar.mqh>`, `<errordescription.mqh>`, `<MQLTA Utils.mqh>`, `<WinUser32.mqh>`), rendering them uncompilable. A compiled MT4 binary (`.ex4`) and a BOM-less UTF-16LE encoded file (`XAU-GU Scalper.mq5`) contaminate the source corpus. Across the include headers, no circular include loops exist, but four headers completely lack include guards, and the `Key_levels_Ulli` family uses a generic collision-prone guard symbol (`ALREADY_INCLUDED`) alongside naked global variable declarations. Strategy logic contains critical money-math vulnerabilities including unhandled division-by-zero on lot calculations, hardcoded quote-currency string parsing, and blocking HTTP `WebRequest` calls that break deterministic backtesting.


- **Fix:** Provide stub or full implementations of `Calendar.mqh`, `errordescription.mqh`, `MQLTA Utils.mqh`, and `WinUser32.mqh` in the include search path, or isolate uncompilable EAs into a quarantined corpus partition.

### [P1] Division by zero in THEHFT lot sizing during zero-stoploss execution
- **Where:** `Testing/Mq5/THEHFT.mq5:539`
- **Confidence:** CONFIRMED
- **Code:**
  ```mql5
  double ticksize  = SymbolInfoDouble(_Symbol, SYMBOL_TRADE_TICK_SIZE);
  double tickvalue = SymbolInfoDouble(_Symbol, SYMBOL_TRADE_TICK_VALUE);
  double lotstep   = SymbolInfoDouble(_Symbol, SYMBOL_VOLUME_STEP);
  
  double moneyPerLotstep = slPoints / ticksize * tickvalue * lotstep;
  lots = MathFloor(risk / moneyPerLotstep) * lotstep;
  ```
- **Failure:** When `LotType > 0` and `CalculatedStopLoss` is 0 (or `ticksize` is 0 before symbol quotes initialize), `slPoints` is 0, causing `moneyPerLotstep` to evaluate to `0.0`. The subsequent division `risk / moneyPerLotstep` divides by zero, resulting in `+Infinity` / `NaN`. `MathFloor` and subsequent math bounds fail, producing invalid trade volumes and throwing runtime floating point exceptions during execution.
- **Fix:** Add a non-zero guard checking `if (slPoints <= 0 || ticksize <= 0 || tickvalue <= 0 || lotstep <= 0) return fixedLots;` before computing `moneyPerLotstep`.

### [P1] Unhandled zero tick size causes division by zero in lot size and pip value calculations
- **Where:** `Testing/Mq5/The REAL-GAINS Algo MT5 M1 EA.mq5:186`
- **Confidence:** CONFIRMED
- **Code:**
  ```mql5
  double tickValue = sym.TickValue();
  double tickSize  = sym.TickSize();
  double lossPerLot = (stopDistance / tickSize) * tickValue;
  if(lossPerLot <= 0) return 0.01;
  ```
- **Failure:** On custom symbol feeds, synthetic instruments, or during engine initialization before symbol market data is resolved, `sym.TickSize()` returns `0.0`. Evaluating `stopDistance / tickSize` produces `NaN`/`Infinity`, causing `lossPerLot` evaluation to fail and corrupting risk-based lot sizing across trades (identical bug present in `XAUUSD XARD FX EA SOURCE CODE.mq5:171`).
- **Fix:** Check `if (tickSize <= 0.0) return minLot;` immediately after retrieving `tickSize` prior to division.

### [P2] BOM-less UTF-16LE file encoding corrupts standard text parsers
- **Where:** `Testing/Mq5/XAU-GU Scalper.mq5:1`
- **Confidence:** CONFIRMED
- **Code:**
  ```text
  2F 00 2F 00 2B 00 2D 00 2D 00 2D 00 2D 00 2D 00 (//+------- in UTF-16LE without BOM)
  ```
- **Failure:** `XAU-GU Scalper.mq5` (12,861 lines, 498,758 bytes) is encoded in Little-Endian UTF-16 but lacks a 2-byte BOM (`0xFF 0xFE`). Standard UTF-8/ASCII readers interpret the stream as containing alternating null bytes `\0`, resulting in truncated file reads or parser syntax errors.
- **Fix:** Normalize all source files in the corpus to UTF-8 with or without standard BOM via an automated repository encoding migration script.

### [P2] Missing include guards permit duplicate symbol definitions
- **Where:** `Testing/Mq5/AutoTrading Scheduler.mqh:1`
- **Confidence:** CONFIRMED
- **Code:**
  ```mql5
  #include "Defines.mqh"
  #include <WinUser32.mqh>

  #import "user32.dll"
  ```
- **Failure:** `AutoTrading Scheduler.mqh`, `Defines.mqh`, `GammaAccelerationEngine.mqh`, and `GammaAccelerationEngineMulti.mqh` contain neither `#ifndef` macro guards nor `#property once` / `#pragma once`. If any of these headers are included by more than one file in a compilation unit, class definitions (`CScheduler`), helper functions, and global constants are defined multiple times, causing compiler redeclaration errors.
- **Fix:** Add standard `#ifndef` include guard macros or `#property once` at the beginning of all four header files.

### [P2] Generic include guard macro collision suppresses independent header loading
- **Where:** `Testing/Mq5/Key_levels_Ulli.mqh:1`
- **Confidence:** CONFIRMED
- **Code:**
  ```mql5
  #ifndef ALREADY_INCLUDED
  #define ALREADY_INCLUDED
  ```
- **Failure:** `Key_levels_Ulli.mqh`, `Key_levels_Ulli (2).mqh`, and `Key_levels_Ulli (3).mqh` all use the generic guard `#ifndef ALREADY_INCLUDED`. If any other library or script defines `ALREADY_INCLUDED`, or if a strategy attempts to include both an indicator and key levels header, the preprocessor silently skips the entire contents of `Key_levels_Ulli.mqh`. Furthermore, the file defines naked global variables (`extern calc_methods calculation_method ...`) in the header scope, causing duplicate symbol linker collisions upon multiple inclusions.
- **Fix:** Replace `ALREADY_INCLUDED` with unique include guard symbols (e.g. `KEY_LEVELS_ULLI_MQH`) and encapsulate global variables inside static class members or local namespaces.

### [P2] Native Win32 DLL import breaks cross-platform execution
- **Where:** `Testing/Mq5/AutoTrading Scheduler.mqh:4`
- **Confidence:** CONFIRMED
- **Code:**

### [P3] Broken quote currency extraction for non-6-character symbols
- **Where:** `Testing/Mq5/XAUUSD XARD FX EA SOURCE CODE.mq5:178`
- **Confidence:** CONFIRMED
- **Code:**
  ```mql5
  string accountCurrency = AccountInfoString(ACCOUNT_CURRENCY);
  string quoteCurrency = StringSubstr(symbol, 3, 3);
  if (quoteCurrency != accountCurrency)
  {
     string conversionPair = quoteCurrency + accountCurrency;
  ```
- **Failure:** Hardcoding `StringSubstr(symbol, 3, 3)` assumes exactly a 6-character currency pair (e.g. `EURUSD` -> `USD`). For equities, indices, and suffixed broker symbols (e.g. `TSLA.nas`, `US500`, `BTCUSD_i`, `EURUSD.m`), `StringSubstr(symbol, 3, 3)` extracts invalid 3-character strings like `A.n`, `500`, or `USD_`. The subsequent `SymbolInfoDouble(conversionPair, SYMBOL_BID)` lookups fail, causing pip values to fall back to an arbitrary hardcoded exchange rate of 1.3.
- **Fix:** Query `SymbolInfoString(symbol, SYMBOL_CURRENCY_PROFIT)` or `SYMBOL_CURRENCY_MARGIN` rather than slicing symbol string names.

### [P3] Extreme template meta-programming and dynamic object allocation complexity
- **Where:** `Testing/Mq5/XAU-GU Scalper.mq5:589`
