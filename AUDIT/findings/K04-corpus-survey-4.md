## Verdict
This partition of the corpus contains 102,228 lines of active trading code across 59 files, dominated in volume by `STAR_v11.20.mq5` (51,397 lines, 2.6 MB) and `Prop-Firm Expert.mq5` (9,602 lines, 523 KB). The structural quality is bifurcated: standard retail EAs cleanly rely on MetaQuotes Standard Library classes (`CTrade` in 38 files, `CPositionInfo` in 12 files), while advanced generators and retail scripts introduce major transpilation barriers. 

Specifically, 1 file is completely corrupted with 7,156 zero bytes (`Simple_Classic_Trailing.mq5`), 1 file is an MQL4 indicator (`SHK Professional Heikin Ashi 1.00.mq4`), 1 file is an MQL5 strategy misplaced with a `.txt` extension (`Simple Classic Trailing Stop Mq5.txt`), 8 files are encoded in UTF-16LE, and 1 massive file (`Prop-Firm Expert.mq5`) uses BOM-less UTF-16LE with multi-argument C++ template classes (`template<typename T1, ...> class MDL_Condition`). Multiple files invoke unconvertible out-of-sandbox operations including Win32 GUI imports via `#import "user32.dll"`, HTTP `WebRequest`, modal `MessageBox` popups, and filesystem persistence (`FileOpen` with `FILE_COMMON`).

## Findings

### [P1] All-NUL corrupted file in test corpus (Simple_Classic_Trailing.mq5)
- **Where:** `Testing/Mq5/Simple_Classic_Trailing.mq5:1`
- **Confidence:** CONFIRMED
- **Code:**
  ```c
  \x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00
  ```
- **Failure:** `Simple_Classic_Trailing.mq5` consists of 7,156 bytes of pure `0x00` (NUL) characters with 0 valid lines of code. When ingested by `Mql5SourceDecoder.Decode()`, it is flagged as `Mql5SourceContentKind.AllNul` (`MQL5_FRONTEND_ALL_NUL_SOURCE`) and compilation is rejected. Meanwhile, the valid source code exists alongside it under the name `Simple Classic Trailing Stop Mq5.txt`.
- **Fix:** Replace `Simple_Classic_Trailing.mq5` with the contents of `Simple Classic Trailing Stop Mq5.txt` and delete the stray `.txt` file.

### [P1] Unhandled C++ template class declarations and BOM-less UTF-16 in visual EA (Prop-Firm Expert.mq5)
- **Where:** `Testing/Mq5/Prop-Firm Expert.mq5:543`
- **Confidence:** CONFIRMED
- **Code:**
  ```cpp
  template<typename T1,typename _T1_,typename T2,typename T3,typename _T3_,typename T4>
  class MDL_Condition: public BlockCalls
  {
  	public: /* Input Parameters */
  	T1 Lo; virtual _T1_ _Lo_(){return(_T1_)0;}
  ```
- **Failure:** `Prop-Firm Expert.mq5` (523,834 bytes, 9,602 lines) is encoded in UTF-16LE without a Byte Order Mark and contains multi-type C++ template classes. When passed to `Mql5Lowering.Lower()`, the lowering engine hits `UnsupportedTemplate` (`MQL5_LOWER_UNSUPPORTED_TEMPLATE`) and poisons the module (`Module: null`), preventing transpilation of visual builder EAs.
- **Fix:** Add a template monomorphization/specialization pass in the front end or flag fxDreema template visual components as unsupported prior to lowering.

### [P1] Out-of-sandbox Win32 DLL import via #import (News Stopper MT5.mq5)
- **Where:** `Testing/Mq5/News Stopper MT5.mq5:23`
- **Confidence:** CONFIRMED
- **Code:**
  ```cpp
     #import "user32.dll"
        HANDLE   GetAncestor(  HANDLE hwnd, uint flags);
        int      PostMessageW( HANDLE hwnd, uint Msg, PVOID param, PVOID param );
     #import
  ```
- **Failure:** The strategy imports `user32.dll` to send Windows messages (`PostMessageW`) to toggle automated trading in the MT5 desktop GUI. In a containerized Linux execution environment or secure sandbox, native Win32 DLL imports fail to link and are blocked with `MQL5_LOWER_UNSUPPORTED_IMPORT_BODY`, terminating the compilation.
- **Fix:** Quarantine or filter DLL imports in the ingestion pre-pass and stub user32 messaging routines for headless execution.

### [P2] Naked pointer allocation and deallocation without null checks (SetFixedSLandTP.mq5)
- **Where:** `Testing/Mq5/SetFixedSLandTP.mq5:80`
- **Confidence:** CONFIRMED
- **Code:**
  ```cpp
      CTrade *Trade;
      Trade = new CTrade;

      int positions_total = PositionsTotal();
  ```
- **Failure:** `Trade` is dynamically allocated via `new CTrade` on every call to `SetFixedSLandTP()` (line 80) and destroyed via `delete Trade;` (line 424) without checking allocation success (`CheckPointer(Trade)`). If an early return occurs (e.g. at line 91, 102, or 120), `delete Trade;` is bypassed, creating repeated memory leaks on every tick in unmanaged MQL5 execution.
- **Fix:** Declare `CTrade Trade;` as an automatic/stack variable or class member rather than allocating and deleting dynamic pointers inside a high-frequency tick routine.

### [P2] Blocking GUI MessageBox dialogs and common filesystem trial probing (Quantum Queen X 4.3.mq5)
- **Where:** `Testing/Mq5/Quantum Queen X 4.3.mq5:326`
- **Confidence:** CONFIRMED
