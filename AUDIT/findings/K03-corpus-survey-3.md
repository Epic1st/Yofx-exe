## Findings

### [P1] Reverse buffer indexing in `GOLD_EMA_Crossover_TSL_EA.mq5` inverts buy and sell signals
- **Where:** `Testing/Mq5/GOLD_EMA_Crossover_TSL_EA.mq5:41-50`
- **Confidence:** CONFIRMED
- **Code:**
  ```mql5
   if(fastEMA[1] < slowEMA[1] && fastEMA[0] > slowEMA[0]) // Bullish crossover
     {
      if(!PositionSelect(_Symbol))
         OpenOrder(ORDER_TYPE_BUY);
     }
   else if(fastEMA[1] > slowEMA[1] && fastEMA[0] < slowEMA[0]) // Bearish crossover
     {
      if(!PositionSelect(_Symbol))
         OpenOrder(ORDER_TYPE_SELL);
     }
  ```
- **Failure:** When `CopyBuffer` copies into dynamic arrays without `ArraySetAsSeries(arr, true)`, MQL5 stores data in standard chronological order (`[0]` is bar 1 / older bar, `[1]` is bar 0 / newest bar). The check `fastEMA[1] < slowEMA[1] && fastEMA[0] > slowEMA[0]` evaluates `current_fast < current_slow && prev_fast > prev_slow` (a bearish crossover / death cross), yet executes `OpenOrder(ORDER_TYPE_BUY)`. Conversely, a golden cross triggers `OpenOrder(ORDER_TYPE_SELL)`. The EA executes trades 100% in reverse of its designed strategy.
- **Fix:** Call `ArraySetAsSeries(fastEMA, true); ArraySetAsSeries(slowEMA, true);` before `CopyBuffer`, or invert the index checks to `fastEMA[0] > slowEMA[0] && fastEMA[1] < slowEMA[1]` for bullish entries.

### [P1] MQL4 `iMA` invocation signature in `mt DanielScalper.mq5` causes compilation failure and corrupted trend evaluation
- **Where:** `Testing/Mq5/mt DanielScalper.mq5:40-42`
- **Confidence:** CONFIRMED
- **Code:**
  ```mql5
   // Calculate moving average for trend direction
   double ma = iMA(_Symbol, PERIOD_CURRENT, MAPeriod, 0, MODE_SMA, PRICE_CLOSE, 0);
   bool isBullish = ask > ma; // Trend is bullish if price is above MA
   bool isBearish = bid < ma; // Trend is bearish if price is below MA
  ```
- **Failure:** In MQL5, `iMA` takes 6 arguments and returns an `int` handle to an indicator cache rather than a price value. `mt DanielScalper.mq5` passes 7 arguments (the legacy MQL4 signature), causing compilation to fail (`'iMA' - wrong parameters count`). In transpilers or MQL4 emulation where `iMA` returns an integer handle (e.g. 10), assigning it to `double ma` causes `ask > ma` to evaluate whether Ask price is greater than the handle ID integer, completely corrupting market trend logic.
- **Fix:** Create the indicator handle in `OnInit()` with `iMA(_Symbol, PERIOD_CURRENT, MAPeriod, 0, MODE_SMA, PRICE_CLOSE)`, allocate a buffer array, and fetch values with `CopyBuffer(handle, 0, 0, 1, buffer)` in `OnTick()`.

### [P1] Hardcoded expiration date kill-switch in `heaven and hell.mq5` permanently aborts initialization
- **Where:** `Testing/Mq5/heaven and hell.mq5:44-59`
- **Confidence:** CONFIRMED
- **Code:**
  ```mql5
  input string ExpiryDate = "2025.11.30";   // Định dạng: YYYY.MM.DD

  //=== HÀM KIỂM TRA HẠN ========================================
  bool CheckExpiry()
  {
     datetime now_time = TimeCurrent();
     datetime expiry_time = StringToTime(ExpiryDate + " 23:59");

     if (now_time > expiry_time)
     {
        PrintFormat("⛔ EA expired on %s — please update version!", ExpiryDate);
        return false;
     }
  ```
- **Failure:** `OnInit()` executes `if (!CheckExpiry()) return INIT_FAILED;` on line 610. Because `ExpiryDate` is hardcoded to "2025.11.30", running this EA in live trading in 2026 or running a backtest spanning dates past November 2025 causes `OnInit()` to immediately return `INIT_FAILED`, completely halting execution.
- **Fix:** Remove the `CheckExpiry` call or set `ExpiryDate` to an unrestricted default value.

### [P1] Synchronous AI/Cloud `WebRequest` calls freeze tick execution and fail in strategy tester
- **Where:** `Testing/Mq5/GoldScalpingEA-1.mq5:605`
- **Confidence:** CONFIRMED
- **Code:**
  ```mql5
   Print("กำลังส่งข้อมูลไปยัง DeepSeek AI...");
   
   // Send request to DeepSeek AI
   int res = WebRequest("POST", AIEndpoint, headers, 30000, post_data, result, headers);
  ```
- **Failure:** In `GoldScalpingEA-1.mq5` (and similarly in `MB_Sniper EA v1.mq5:802`, `Hon-Matrix.mq5:430`, `GoldReaper_MT5_ECN_Patched (1).mq5:9933`, and `Lizard_1.85.mq5:10304`), synchronous `WebRequest` calls with up to 30,000ms timeouts are invoked from the main execution thread. In the MT5 Strategy Tester and offline backtest environments, `WebRequest` returns -1 with error 4060 (`ERR_FUNCTION_NOT_ALLOWED`), forcing fallback behavior on every tick and stalling live execution during network latency.
- **Fix:** Decouple external API calls into background tasks and provide mocked response providers during backtests.

### [P2] Compiled binary file committed with `.mq5` source extension in `Lopez Strategy EA.mq5` breaks transpilers
- **Where:** `Testing/Mq5/Lopez Strategy EA.mq5:1`
- **Confidence:** CONFIRMED
- **Code:**
  ```text
  45 58 2D 02 70 00 62 09 00 10 00 00 00 80 00 00 E4 04 00 00 00 00 00 00... (EX- header)
  ```
- **Failure:** `Lopez Strategy EA.mq5` (289,472 bytes) is not an MQL5 text source file but a compiled `.ex5` binary executable from fxDreema starting with the `EX-` magic header. Source transpilers and lexers attempting to parse this file crash on non-text binary bytes.
- **Fix:** Rename the file to `Lopez Strategy EA.ex5` and add magic byte validation to reject binary files in source ingestion pipelines.

### [P2] UTF-16LE encoding without BOM in `MM3.0 FLIP CODEPRO.mq5` breaks UTF-8 stream readers
- **Where:** `Testing/Mq5/MM3.0 FLIP CODEPRO.mq5:1`, `Testing/Mq5/MM3.0 FLIP CODEPRO (2).mq5:1`
- **Confidence:** CONFIRMED
- **Code:**
  ```mql5
  //+------------------------------------------------------------------------------+//
  //)   ____  _  _  ____  ____  ____  ____  __  __    __      ___  _____  __  __   (//
  ```
- **Failure:** `MM3.0 FLIP CODEPRO.mq5` (523,482 bytes, 9,384 lines) and `MM3.0 FLIP CODEPRO (2).mq5` (528,534 bytes, 9,446 lines) are encoded in 16-bit little-endian Unicode without a 0xFF 0xFE BOM header. Standard UTF-8 stream readers encounter alternating null bytes (`0x00`), causing lexical analyzers to terminate parsing.
- **Fix:** Implement null-byte preamble inspection to detect BOM-less UTF-16LE files during ingestion.

### [P3] Hardcoded 2-decimal lot normalization causes invalid volume errors on non-forex instruments
- **Where:** `Testing/Mq5/GoldFlow_H1_AutoRegime.mq5:524`, `Testing/Mq5/GridTrendPro.mq5:195`, `Testing/Mq5/HedgeGridEA_v2.mq5:316`, `Testing/Mq5/lwHiddenSmashDayContextExpert.mq5:556`, `Testing/Mq5/MeffsMomentumBurst_v8.mq5:496`, `Testing/Mq5/MForex 1.02 (converted by @ivanchodev27).mq5:131`
- **Confidence:** CONFIRMED
- **Code:**
  ```mql5
  return NormalizeDouble(lot, 2);
  ```
- **Failure:** Hardcoding `NormalizeDouble(lot, 2)` forces trade volume to 2 decimal places. On crypto pairs requiring 3-decimal precision (e.g. 0.001 min lot) or indices requiring integer lots (e.g. US30 lot step 1.0), this normalization causes `OrderSend` to fail with `TRADE_RETCODE_INVALID_VOLUME`.
- **Fix:** Compute lot precision dynamically from `SymbolInfoDouble(_Symbol, SYMBOL_VOLUME_STEP)`.

## Findings

### [P1] Reverse buffer indexing in `GOLD_EMA_Crossover_TSL_EA.mq5` inverts buy and sell signals
- **Where:** `Testing/Mq5/GOLD_EMA_Crossover_TSL_EA.mq5:41-50`
- **Confidence:** CONFIRMED
- **Code:**
  ```mql5
   if(fastEMA[1] < slowEMA[1] && fastEMA[0] > slowEMA[0]) // Bullish crossover
     {
      if(!PositionSelect(_Symbol))
         OpenOrder(ORDER_TYPE_BUY);
     }
   else if(fastEMA[1] > slowEMA[1] && fastEMA[0] < slowEMA[0]) // Bearish crossover
     {
      if(!PositionSelect(_Symbol))
         OpenOrder(ORDER_TYPE_SELL);
     }
  ```
- **Failure:** When `CopyBuffer` copies into dynamic arrays without `ArraySetAsSeries(arr, true)`, MQL5 stores data in standard chronological order (`[0]` is bar 1 / older bar, `[1]` is bar 0 / newest bar). The check `fastEMA[1] < slowEMA[1] && fastEMA[0] > slowEMA[0]` evaluates `current_fast < current_slow && prev_fast > prev_slow` (a bearish crossover / death cross), yet executes `OpenOrder(ORDER_TYPE_BUY)`. Conversely, a golden cross triggers `OpenOrder(ORDER_TYPE_SELL)`. The EA executes trades 100% in reverse of its designed strategy.
- **Fix:** Call `ArraySetAsSeries(fastEMA, true); ArraySetAsSeries(slowEMA, true);` before `CopyBuffer`, or invert the index checks to `fastEMA[0] > slowEMA[0] && fastEMA[1] < slowEMA[1]` for bullish entries.

### [P1] MQL4 `iMA` invocation signature in `mt DanielScalper.mq5` causes compilation failure and corrupted trend evaluation
- **Where:** `Testing/Mq5/mt DanielScalper.mq5:40-42`
- **Confidence:** CONFIRMED
- **Code:**
  ```mql5
   // Calculate moving average for trend direction
   double ma = iMA(_Symbol, PERIOD_CURRENT, MAPeriod, 0, MODE_SMA, PRICE_CLOSE, 0);
   bool isBullish = ask > ma; // Trend is bullish if price is above MA
   bool isBearish = bid < ma; // Trend is bearish if price is below MA
  ```
- **Failure:** In MQL5, `iMA` takes 6 arguments and returns an `int` handle to an indicator cache rather than a price value. `mt DanielScalper.mq5` passes 7 arguments (the legacy MQL4 signature), causing compilation to fail (`'iMA' - wrong parameters count`). In transpilers or MQL4 emulation where `iMA` returns an integer handle (e.g. 10), assigning it to `double ma` causes `ask > ma` to evaluate whether Ask price is greater than the handle ID integer, completely corrupting market trend logic.
- **Fix:** Create the indicator handle in `OnInit()` with `iMA(_Symbol, PERIOD_CURRENT, MAPeriod, 0, MODE_SMA, PRICE_CLOSE)`, allocate a buffer array, and fetch values with `CopyBuffer(handle, 0, 0, 1, buffer)` in `OnTick()`.

### [P1] Hardcoded expiration date kill-switch in `heaven and hell.mq5` permanently aborts initialization
- **Where:** `Testing/Mq5/heaven and hell.mq5:44-59`
- **Confidence:** CONFIRMED
- **Code:**
  ```mql5
  input string ExpiryDate = "2025.11.30";   // Định dạng: YYYY.MM.DD

  //=== HÀM KIỂM TRA HẠN ========================================
  bool CheckExpiry()
  {
     datetime now_time = TimeCurrent();
     datetime expiry_time = StringToTime(ExpiryDate + " 23:59");

     if (now_time > expiry_time)
     {
        PrintFormat("⛔ EA expired on %s — please update version!", ExpiryDate);
        return false;

  ```
- **Failure:** `OnInit()` executes `if (!CheckExpiry()) return INIT_FAILED;` on line 610. Because `ExpiryDate` is hardcoded to "2025.11.30", running this EA in live trading in 2026 or running a backtest spanning dates past November 2025 causes `OnInit()` to immediately return `INIT_FAILED`, completely halting execution.
- **Fix:** Remove the `CheckExpiry` call or set `ExpiryDate` to an unrestricted default value.

### [P3] Hardcoded 2-decimal lot normalization causes invalid volume errors on non-forex instruments
- **Where:** `Testing/Mq5/GoldFlow_H1_AutoRegime.mq5:524`, `Testing/Mq5/GridTrendPro.mq5:195`, `Testing/Mq5/HedgeGridEA_v2.mq5:316`, `Testing/Mq5/lwHiddenSmashDayContextExpert.mq5:556`, `Testing/Mq5/MeffsMomentumBurst_v8.mq5:496`, `Testing/Mq5/MForex 1.02 (converted by @ivanchodev27).mq5:131`
