## Verdict
This segment of the corpus contains approximately 31,900 lines across 33 files representing real-world algorithmic trading scripts ranging from pure standard-library EAs (`ExpertMAPSARSizeOptimized.mq5`) and modern AI LLM integrations (`EA-MT5-OPENAI.mq5`) to decompiled legacy MQL4 code wrapped in MQL5 compatibility layers (`Elise-EA.mq5`, `Engine.mqh`, `DAY TRADING FOREX.txt`), visual builder artifacts (`EA Correlations.mq5`), and truncated stub files (`FIB 2.mq5`).

The overall quality of the EAs is mixed: 8 files are encoded in UTF-16LE (one with raw null bytes and no BOM), 6 files are byte-for-byte duplicate copies, 2 files are MQL source stored in `.txt` extensions, and 1 file is an unextracted `.zip` archive. Multiple EAs contain severe logic flaws (including reverse array indexing that inverts buy/sell signals, broken Martingale order history tracking, and TakeProfit formulas that overwrite targets with StopLoss pips). Furthermore, several constructs (synchronous WebRequest calls, direct chart window manipulation, and legacy MQL4 indicator plotting functions) will not survive direct transpilation to C# without dedicated runtime support.

## Findings

### [P1] Reverse buffer indexing in `CRUDE_OIL_EMA_Crossover_TSL_EA.mq5` inverts buy and sell signals
- **Where:** `Testing/Mq5/CRUDE_OIL_EMA_Crossover_TSL_EA.mq5:41-50`
- **Confidence:** CONFIRMED
- **Code:**
  ```mql5
   if(fastEMA[1] < slowEMA[1] && fastEMA[0] > slowEMA[0]) // Bullish crossover
     {
      if(!PositionSelect(_Symbol))
         OpenOrder(ORDER_TYPE_BUY);
     }
   else if(fastEMA[1] > slowEMA[1] && fastEMA[0] < slowEMA[0]) // Bearish crossover
     {
      if(!PositionSelect(_Symbol))
         OpenOrder(ORDER_TYPE_SELL);
     }
  ```
- **Failure:** When `CopyBuffer` copies into dynamic arrays without `ArraySetAsSeries(arr, true)`, MQL5 stores data in standard chronological order (`[0]` is bar 1 / older bar, `[1]` is bar 0 / newest bar). The check `fastEMA[1] < slowEMA[1] && fastEMA[0] > slowEMA[0]` evaluates `current_fast < current_slow && prev_fast > prev_slow` (a bearish crossover / death cross), yet executes `OpenOrder(ORDER_TYPE_BUY)`. Conversely, a golden cross triggers `OpenOrder(ORDER_TYPE_SELL)`. The EA executes trades 100% in reverse of its designed strategy.
- **Fix:** Call `ArraySetAsSeries(fastEMA, true); ArraySetAsSeries(slowEMA, true);` before `CopyBuffer`, or invert the index checks to `fastEMA[0] > slowEMA[0] && fastEMA[1] < slowEMA[1]` for bullish entries.

### [P1] Deal history inspection in `free_money_expert_robot_bot_hide_sl_and_tp_fixed_for_backtest.mq5` inspects entry deals and breaks Martingale lot sizing
- **Where:** `Testing/Mq5/free_money_expert_robot_bot_hide_sl_and_tp_fixed_for_backtest.mq5:66-88`
- **Confidence:** CONFIRMED
- **Code:**
  ```mql5
         if (HistoryDealGetString(ticket, DEAL_SYMBOL) == _Symbol &&
             (HistoryDealGetInteger(ticket, DEAL_TYPE) == DEAL_TYPE_BUY ||
              HistoryDealGetInteger(ticket, DEAL_TYPE) == DEAL_TYPE_SELL))
         {
            datetime closeTime = (datetime)HistoryDealGetInteger(ticket, DEAL_TIME); // Fix: cast to datetime
            if (closeTime > latestCloseTime)
            {
               latestCloseTime = closeTime;
               lastDeal = ticket;
               profit = HistoryDealGetDouble(ticket, DEAL_PROFIT);
            }
         }
  ```
- **Failure:** In MT5, position opening deals (`DEAL_ENTRY_IN`) also possess `DEAL_TYPE_BUY` or `DEAL_TYPE_SELL` with `DEAL_PROFIT == 0.0`. When a position is entered, its entry deal becomes the latest deal in history. Because line 85 checks `if (profit >= 0) currentLot = LotSize;`, the EA evaluates the newly opened entry deal as a winning exit, immediately resetting `currentLot` back to `LotSize` and destroying the Martingale multiplier progression after losses.
- **Fix:** Add `&& HistoryDealGetInteger(ticket, DEAL_ENTRY) == DEAL_ENTRY_OUT` to the deal inspection filter so only closed trade deals are evaluated for profit calculation.

### [P1] Inverted TakeProfit recalculation in `cm_SL-NL-TP.mq5` overwrites TakeProfit with Stoploss distance
- **Where:** `Testing/Mq5/cm_SL-NL-TP.mq5:58`
- **Confidence:** CONFIRMED
- **Code:**
  ```mql5
            if (Takeprofit!=0)
            {
               request.tp = NormalizeDouble(OOP + Takeprofit * _Point,_Digits);
               if (request.tp<=Ask) request.tp = NormalizeDouble(Ask + Stoploss * _Point,_Digits);
               if (request.tp > OTP && OTP!=0) request.tp = OTP;
            }
  ```
- **Failure:** In `cm_SL-NL-TP.mq5`, when a Buy position's calculated TP is at or below the Ask price (line 58) or a Sell position's TP is at or above Bid (line 94), the code attempts to shift the TP beyond current market price. However, line 58 adds `Stoploss * _Point` instead of `Takeprofit * _Point` (and line 94 subtracts `Stoploss * _Point`). If `Stoploss` is 500 points and `Takeprofit` is 200 points, invalid TPs are enlarged by 250%, distorting risk-reward parameters.
- **Fix:** Replace `+ Stoploss * _Point` on line 58 and `- Stoploss * _Point` on line 94 with `+ Takeprofit * _Point` and `- Takeprofit * _Point`.

### [P1] Synchronous WebRequest in `EA-MT5-OPENAI.mq5` blocks tick processing for up to 10 seconds and crashes in strategy tester
- **Where:** `Testing/Mq5/EA-MT5-OPENAI.mq5:2134-2136`
- **Confidence:** CONFIRMED
- **Code:**
  ```mql5
   // Make the API call
   int timeout = 10000; // 10 seconds timeout
   int res = WebRequest("POST", "https://api.openai.com/v1/chat/completions", 
                        headers, timeout, postData, result, resultHeaders);
  ```
- **Failure:** Executing a blocking HTTP POST with a 10-second timeout inside the main `OnTick` / `OnTimer` thread freezes order execution, stops, and tick tracking during high market volatility. Additionally, MT5 prohibits `WebRequest` during backtests (returning error 4060 / ERR_FUNCTION_NOT_ALLOWED), forcing the EA into fallback mode on every test run.
- **Fix:** Decouple LLM calls into asynchronous background workers and inject mock response fixtures for deterministic backtesting.

### [P2] Invalid `OnDeinit` signature and deprecated MQL4 plotting functions in `DAY TRADING FOREX.txt` prevent MQL5 compilation
- **Where:** `Testing/Mq5/DAY TRADING FOREX.txt:90-93`
- **Confidence:** CONFIRMED
- **Code:**
  ```mql5
  int OnDeinit(const int reason) {
     f0_12();
     return(INIT_SUCCEEDED);
  }
  ```
- **Failure:** In MQL5, `OnDeinit` must return `void`. Returning `int` with `return(INIT_SUCCEEDED)` fails compilation with `'OnDeinit' - function must return 'void'`. Furthermore, lines 72-78 call legacy MQL4 APIs (`SetIndexStyle`, `SetIndexArrow`, `IndicatorDigits`) which do not exist in the MQL5 runtime.
- **Fix:** Change return type to `void OnDeinit(const int reason)` (removing the return value) and migrate indicator styling to `PlotIndexSetInteger` / `IndicatorSetInteger`.

### [P2] UTF-16LE encoding without BOM in `EA Correlations.mq5` breaks UTF-8 transpiler tokenizers
- **Where:** `Testing/Mq5/EA Correlations.mq5:1`
- **Confidence:** CONFIRMED
- **Code:**
  ```mql5
  //+------------------------------------------------------------------------------+//
  //)   ____  _  _  ____  ____  ____  ____  __  __    __      ___  _____  __  __   (//
  ```
- **Failure:** `EA Correlations.mq5` (481,708 bytes) is stored in 16-bit little-endian Unicode without a 0xFF 0xFE BOM header. Standard UTF-8 decoders interpret every alternate byte as `0x00` (NUL), causing lexical analyzers to encounter unexpected null characters and abort parsing.
- **Fix:** Enhance file ingestion to detect alternating null bytes in header preambles and decode using UTF-16LE fallback when no BOM is present.

### [P3] Hardcoded 2-decimal lot normalization in `EA_ULTRA_AGGRESSIVE.mq5` causes invalid volume errors on non-forex assets
- **Where:** `Testing/Mq5/EA_ULTRA_AGGRESSIVE.mq5:469`
- **Confidence:** CONFIRMED
- **Code:**
  ```mql5
     lot = MathFloor(lot / lot_step) * lot_step;
     lot = MathMax(sym.LotsMin(), lot);
     lot = MathMin(sym.LotsMax(), lot);
     lot = NormalizeDouble(lot, 2);
  ```
- **Failure:** Hardcoding `NormalizeDouble(lot, 2)` forces trade volume to 2 decimal places. - **Fix:** Compute lot precision dynamically from `sym.LotsStep()` instead of hardcoding 2 decimals.
